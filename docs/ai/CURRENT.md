# 현재 작업 — Bonifacio Notes 디자인 전환

- 날짜: 2026-10-20 KST
- 목표: 카테고리가 올라갈 때 글자도 자연스럽게 커지고 이전 항목은 작아지며 내려가게 한다. 카테고리 목록에서 글을 열 때 활성 항목이 아래로 내려갔다 다시 올라오는 현상을 없앤다. 기존 공통 컴포넌트, All notes의 `collection.`, 자동 화면 이동 제거, 소개 접힘 조건, 타일 디자인·모션을 유지한다.
- 완료 조건: 홈, 목록/타일, 글 상세, 검색, 모바일 인덱스가 일관되게 동작하고 프런트엔드 테스트·빌드 및 대표 화면 검증을 통과한다.
- 제약: 기존 공개 콘텐츠/API 계약·본문 sanitizer 유지. 2026-10-20 후속 요청으로 이번 디자인 변경의 커밋·푸시와 main 반영을 승인받았다. 운영 DB 직접 변경은 범위 밖이다. main에 먼저 들어간 Bonifacio 복귀 링크와 배포 설정을 보존하며 dev·cursor 브랜치는 변경하지 않는다.
- 구현: 기본 타일, `view=list`로 목록 선택(기존 `view=tiles` 호환). 가로로 이어지는 대형 제목, read/explore/search 세로 메뉴, 큰 분류·글 제목·검색 제목, 왼쪽 축 회전 및 시간차 진입. 표시용 글꼴은 Segoe UI Light/Helvetica Neue 계열, 타일은 기존 Manrope. 타일 전용 CSS 40개 블록과 PostList 마크업·모션은 보존했다. 관련 파일은 `apps/web/src/App.tsx`, `styles.css`, `App.test.tsx`, `main.tsx`.
- 소개와 경로: HomeIntro를 공통 제목 아래에 유지하며 0.72초 동안 높이(auto↔0)와 세로 위치(0%↔-100%)를 함께 전환한다. 접히는 즉시 inert·aria-hidden을 적용하고 동작 줄이기에서는 즉시 전환한다. 홈 카테고리는 `/?category=…`로 필터링하며 소개 영역을 유지하고, 게시글·읽기 목록에서는 `/notes?category=…`로 이동하며 접힘을 유지한다. All notes는 보기 방식을 유지하며 홈 `/`으로 돌아와 소개를 펼친다. 글↔목록에서는 공통 제목과 카테고리 메뉴 DOM을 유지한다.
- 최신 후속 수정: 홈과 읽기 화면 모두 CategoryLinks의 2행 grid와 위치 애니메이션을 사용한다. All notes에서는 윗줄에 `collection.`이 표시된다. 다른 분류를 누르면 같은 링크 DOM이 원래 자리에서 윗줄로 올라가고 이전 선택은 아랫줄로 돌아간다(0.55초). 홈의 별도 분류 제목은 제거했다. 모바일 메뉴만 세로 메뉴 배치를 유지한다. PanoramaHeading은 `s`의 절반과 점이 남도록 이동 거리를 측정하며 문구 순서와 기존 슬라이드를 유지한다.
- 글자 크기와 글 진입 보완: 링크의 위치 애니메이션 안에서 이름의 크기도 같은 0.55초 감속 곡선으로 전환한다. 건수는 크기를 유지하며 위치만 이동하고 동작 줄이기를 따른다. 글 진입 시 API 응답까지 활성 카테고리가 undefined가 되던 것이 왕복 모션의 원인이었다. 목록·타일·관련 글·검색 링크에서 이미 알려진 `post.category`를 라우터 state로 전달하고, 상세 응답을 받은 뒤에는 서버의 카테고리를 사용한다.
- 화면 위치: 카테고리 링크와 All notes에 `preserveScroll`을 전달하고 카테고리 선택 시 자동 세로·가로 스크롤을 제거했다. 목록 조회 중에는 직전 결과 높이를 유지해 로딩 순간의 화면 높이 축소를 막는다. 명시적인 read/explore 앵커와 일반 게시글 진입의 이동, 검색·모바일 메뉴의 키보드 포커스 복원은 유지한다.
- 공통 컴포넌트 정리: 홈·읽기 화면·모바일 메뉴는 원래도 CategoryLinks를 공유했다. 재사용 경계를 명확히 하도록 `apps/web/src/CategoryLinks.tsx`로 분리하고 호출부의 className/promoteActive 조합을 `variant="index" | "reading" | "menu"`로 통합했다. 활성 상태·건수·이동·모션과 All notes의 링크 마크업을 한곳에서 관리한다. URL 생성은 `navigation.ts`, 공통 감속 곡선은 `motion.ts`를 공유한다. 기존 표시와 동작은 유지하며 Vitest 17개, TypeScript/Vite 빌드, 변경 파일 ESLint를 다시 통과했다.
- 상태: 글자 크기 전환과 글 진입 시 선택 상태 유지 구현·검증 완료. 최종 Vitest 18개, TypeScript/Vite 빌드, 변경 TSX ESLint·Prettier 통과. 상세 응답을 지연한 회귀 테스트에서 글 진입 직후·로딩 중·응답 후 동일한 링크가 계속 활성화되어 있음을 확인한다. 코덱스 브라우저의 1280px 및 390px에서 새 글자의 점진적 확대와 이전 글자의 축소를 측정했다. Homebrew→DesignPattern→Front Controller의 글 전환 표본 모두 DesignPattern 활성 상태·크기를 유지했다. console error/warn 0, 모바일 가로 넘침 0px. CSS와 타일 모션은 변경하지 않았으며 PostList에는 라우터 state 전달만 추가했다.
- main 통합: 디자인 커밋 `b8e2a1e`에 원격 main `055768f`를 병합했다. App.tsx/styles.css의 충돌은 새 헤더에 Bonifacio 복귀 링크를 유지하는 방식으로 해결했다. 모바일에서는 화살표를 표시하며 접근성 이름과 44px 클릭 영역을 유지한다. main의 배포 키 검증·컨테이너 자원 제한도 그대로 포함했다. 병합 결과의 프런트엔드 테스트 18개, TypeScript, 변경 TS ESLint 통과. 1280/320px 헤더의 링크·검색·Index가 겹치지 않으며 가로 넘침 0px를 확인했다. 최종 전체 빌드·통합 검증은 main CI가 수행한다.
- 검증: 최종 Vitest 17개, TypeScript/Vite 빌드, 변경 TSX ESLint·포맷 통과. 코덱스 브라우저에서 Front Controller→Git 8개 타일, 목록 전환→DesignPattern 6개→글 열기→뒤로 가기→새로고침의 상태 유지 확인. 글→목록 전환 전후 제목/메뉴 좌표 동일. 모바일 메뉴에서 Java 12개 탐색 및 390px 목록/타일 시각 확인, 320px 넘침 0px. console error/warn 0. 타일 CSS 40개 블록 동일, PostList는 링크의 view 전달만 추가. Nginx SPA fallback은 기존 설정으로 새 경로 지원. 상세는 `docs/RESPONSIVE_QA.md`.
